const ROOM_CORNERS_BY_SCENE = {
  'room-1': { target: new THREE.Vector3(1.35, 1.0, 1.35), corners: [...4 corners...] },
  'room-2': { target: new THREE.Vector3(1.35, 1.0, 1.35), corners: [...4 corners...] },

let _activeRoomTarget = ROOM_CORNERS_BY_SCENE['room-1'].target;
const cornerHotspots = [];
function rebuildCornerHotspots(sceneId) {
  cornerHotspotsLayer.innerHTML = '';
  cornerHotspots.length = 0;
  const cfg = ROOM_CORNERS_BY_SCENE[sceneId];
  if (!cfg) return;
  _activeRoomTarget = cfg.target;
  for (const c of cfg.corners) {
    const btn = document.createElement('button');
    btn.className = 'corner-hotspot';
    btn.setAttribute('type', 'button');
    btn.setAttribute('aria-label', c.id);

    btn.addEventListener('click', () => orbit.flyTo(c.camPos, _activeRoomTarget));
    cornerHotspotsLayer.appendChild(btn);
    cornerHotspots.push({ btn, world: c.dotWorld, camPos: c.camPos });
  }
}
rebuildCornerHotspots('room-1');

## Architecture and design notes

### The per-scene corner-hotspot pattern (NEW this session)
Before today, room-1 was the only scene with floating 3D dot navigation. The refactor generalizes this so any scene can have dots:

```
ROOM_CORNERS_BY_SCENE = {
  '<scene-id>': {
    target: THREE.Vector3,        // where camera looks after flyTo
    corners: [
      { id, dotWorld, camPos }    // dotWorld = where the dot appears in 3D space;
                                  // camPos = where camera lands after click
    ]
  }
}
```

To add a new room: define a `'room-N'` key with a target Vector3 and an array of corners. The system handles projection, button creation, click handler, and per-frame screen-space update automatically. `switchScene()` calls `rebuildCornerHotspots(id)` which wipes the layer and rebuilds for the new scene. Layer is hidden when no entry in the dict matches.

### The wall-reference workflow (workflow pattern, not code)
1. User uses plain-English: "in [room], the [item] must be in the corner of [wall-A] and [wall-B], [optional orientation/facing]."
2. Translate item name to code identifier (watch for aliases: cabinet=bi-fold, shelf=hutch, cabinet-wall=closet-wall).
3. Translate corner spec to coordinate ranges using the room's wall constants (RW, RD, etc.).
4. If orientation matters, ask clarification.
5. Apply consolidated edits — header coords + all dependent internal offsets in one edit pass.
6. Report done with a one-line "what to look for" hint for the user to verify in browser.
7. User reloads, verifies, moves to next item.

### Outstanding architecture decisions
- **Wall labels (3D text).** Not yet implemented. Options: (a) visible 3D text labels on each wall (clutters the render), (b) hover-tooltip text shown only in some debug mode, (c) skip — the wall-reference workflow alone may make labels unnecessary. **Decide with user before building.**
- **Facing-axis abstraction for orient-able furniture.** Pieces like the hutch encode their orientation through hardcoded offsets to back/front anchors. Future work could introduce a `facing` variable per piece so flipping orientation is one constant change instead of 22 coord edits.
