## Learnings and discoveries

### Three.js r184 WebGPU runtime quirks (May 2026)

These are non-obvious and will bite again next time:

1. **WebGPURenderer init is async** — `await renderer.init()` BEFORE any rendering or `PostProcessing` construction. Constructor returns immediately; backend (WebGPU adapter or WebGL2 fallback) isn't ready until init resolves.
2. **`renderer.capabilities` is undefined on WebGPURenderer**. WebGL-specific API. Anisotropy cap is 16 universally on WebGPU.
3. **`PostProcessing.render()` is sync, `renderAsync()` is deprecated** in r184. Use `render()` in your RAF loop.
4. **TSL post-processing helpers (bloom/fxaa/smaa/ao) are NOT in `three.tsl.min.js`**. They live in `examples/jsm/tsl/display/<NodeName>.js`. The minified TSL build exports only the core node graph helpers (`pass`, `mrt`, `output`, `normalView`, `vec3`, `vec4`, etc.).
5. **WebGPU postprocessing addons import from BOTH `'three'` and `'three/webgpu'`**. The importmap must map BOTH to `three.webgpu.min.js` even though they point to the same file.
6. **Bloom function returns the additive bloom layer**, not a composited result. Compose with `.add()`: `lit.add(bloom(lit, ...))`.
7. **FXAA is a function, not a method**: `fxaa(node)` not `node.fxaa()`.
8. **GTAO requires MRT for normals**: `scenePass.setMRT(mrt({ output: output, normal: normalView }))`. Compose with multiply: `sceneCol.mul(vec4(vec3(aoOcclusion.r), 1.0))`.
9. **`RectAreaLightUniformsLib.js` is WebGL-only — fatal import error in WebGPU**. Use `RectAreaLightTexturesLib.js` instead AND wire it: `THREE.RectAreaLightNode.setLTC(RectAreaLightTexturesLib.init())`.
10. **AgXToneMapping is available** as `THREE.AgXToneMapping` in r184 webgpu build. So is `NeutralToneMapping` (Khronos KhronosNeutral). AgX is cinematically closer to Blender's default.
11. **`transmissionResolutionScale`** is a valid MeshPhysicalMaterial property in r184 — values 0..1 control transmission resolution.

### Bake pipeline

- **Blender 5.1.1 supports OptiX baking** despite older docs claiming otherwise. The existing `ozu-test/bake/bake_room1_chair.py` pattern works as-is.
- **2× A6000 GPUs available**, both idle by default. Use `CUDA_VISIBLE_DEVICES=0` and `=1` to run two bakes in parallel.

## Architecture and design notes

### Layered project hierarchy (re-affirmed)
- **Platform**: `index.html` (the hub) — now shows 7 projects.
- **Project**: `bbq-test.html` — single-file standalone sandbox.
- **No spawning of separate URLs/ports** for interior views (per memory `project_three_layer_hierarchy.md`).

### Per-material texture-set cloning pattern
- Each baked PNG is loaded ONCE via `THREE.TextureLoader`.
- When a material needs a specific `.repeat` (e.g. 6×1 for plank stretch vs 2×2 for stainless surface), the texture is cloned via `cloneSet(set, repeatU, repeatV)` — clones share GPU upload but get independent `.repeat` settings. Important because `.repeat` is a per-texture property, not per-material.

### Per-plank deck colour variation pattern
- Base brown slab + per-plank tinted overlay strips, each with its own `MeshPhysicalMaterial` clone using the SAME texture set but a different `.color` tint multiplied into the albedo map.
- 13 unique materials, all sharing the same texture upload (so GPU memory cost is low).

### Hinge-group pattern for the open cabinet door
- Cabinet doors are children of a `THREE.Group` whose origin is at the outer vertical edge of each door (the hinge axis).
- Right door rotates `-75°` around Y to swing open outward toward operator (toward `-Z`).
- Same pattern is reusable for the future "lid open" alternate state, though the lid is currently closed.

### Lighting follows Kumamoto 11 AM JST daylight rule
- Sun azimuth 160° (SSE), elevation 60°, neutral-cool 5500K (`0xf6f5ec`).
- Back wall faces NORTH per typical Japanese plot orientation, so the back wall is in shadow → no direct sun in the deck.
- Three-piece rig (per CLAUDE.md): sun directional + cool sky-fill directional (over the yard, pointing into deck) + RectAreaLight overhead sky disc + HemisphereLight + HDRI environment.

### Procedural-bake-only material workflow
- Per CLAUDE.md cutting-edge rule, every object pass writes a bake script. This session wrote 5 fresh scripts plus actually ran them on the A6000 (the rule mandates RUNNING, not just writing).
- All shaders are procedural (Wave, Noise, Voronoi nodes) — no external image files. Matches the existing house style (`ozu-test/bake/bake_room1_*.py`).
- Output format: 4 PNGs per material (albedo/normal/roughness/ao) at 2048² with 512 Cycles samples.

### WebGPU + WebGL2 fallback
- WebGPURenderer auto-falls back to WebGL2 if WebGPU is unavailable (verified via Three.js docs, not user-tested).
- Loading overlay has a `if (!('gpu' in navigator))` pre-flight that shows a fallback message — but the WebGL2 fallback should preempt this in practice.
