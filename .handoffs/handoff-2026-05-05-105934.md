## Architecture and design notes

**Cross-host context divergence pattern (this session was the first occurrence):** the user uses two machines for this project — a Mac and a Linux box. Both have access to the same git repo via the project folder, but the system-level state diverges (Node installed on Mac, not on Linux; Obsidian vault on Mac, not Linux). When the user pastes terminal output from one machine into a session running on the other, it can look like continuous work but isn't.

**Tells to detect cross-host pasted output:**
- `ttys000` / `ttys001` etc. → Mac (BSD-style tty)
- `pts/0` / `tty1` → Linux
- `➜  ~` (oh-my-zsh default) — appears on both, but often Mac
- Any reference in pasted output to "yesterday on your Mac" or "this Mac" → it's Mac
- Any path starting with `/Users/riaan/...` → Mac filesystem
- Any path starting with `/home/moha/...` → this Linux box

**Sandbox interactivity limit:** Claude Code's Bash tool runs commands in a non-interactive subshell with no TTY. This means:
- `sudo` for any operation requiring a password fails immediately
- `git rebase -i`, `git add -i`, any other `-i` interactive flag fails
- `apt-get install` is fine (`-y` skips prompts; `-y` is implicit when running as root, but we never run as root from sandbox)
- Workaround: prefix with `!` so the user runs it in their actual interactive shell, output is captured back into the Claude conversation

**Skill install mental model (for future reference):** the `skills` CLI is itself a Node app distributed via npm. It clones GitHub repos that contain `SKILL.md` files (the skill manifest format) and either symlinks or copies them into the appropriate agent skills folder (`~/.claude/skills/` for Claude Code globally, `./.claude/skills/` for project-local). Multiple agents are supported (`claude-code`, `cursor`, others). The `-g` flag means "user-level / global" — install once, available across all projects on this machine.
