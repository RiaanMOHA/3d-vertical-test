### The 3-layer rule is a hard constraint, not a guideline

Multiple times in this and prior sessions, the user has stated the rule as: "1 project, 1 URL." The platform `index.html` lists projects ("test", "Ozu-1"). Each project is ONE HTML file with the exterior + chips. ### Window heights and Japanese codes

- 引違 (sliding double-pane): WWWHH where WWW is 100mm width units and HH is 100mm height units.
  - `11909` = 1.69m × 0.9m (used for 2F room2/room3)
  - `15009` = 1.50m × 0.9m (used for 2F room1/bedroom, also 1F LDK back)
  - `16009` = 1.60m × 0.9m (1F LDK back)
  - `16020` = 1.60m × 2.0m (1F LDK garden door — full height!)
- 縦すべり (vertical casement): smaller windows.
  - `02609` = 0.26m × 0.9m (typical privacy/casement)
  - `02607` = 0.26m × 0.7m
- 横すべり窓 (horizontal awning): small slim windows.
  - `03603` = 0.36m × 0.3m (toilet)
  - `06003` = 0.60m × 0.3m (washroom)
- "FL+1800" / "FL+1900" / "FL+2000" = top of window above floor level. Bottom = top - height.
- Most 2F windows: FL+2000, 0.9m tall → y range 1.10..2.00 (relative to F2 floor).
- Most 1F windows: FL+1800 or FL+1900 → bottom varies by window height.
- 1F LDK 16020 garden door: y=0 to 2.0 (full-height; goes to floor — no sill).

### Window helper architecture: x-gap merge + post-pass for sill/lintel/glass

Pattern that works for both floors:
1. Build outer wall via `wallX(z, a, b, gaps, height, yBase)` where `gaps` includes BOTH door full-height openings AND window x-ranges. The wallX helper just leaves those x-ranges blank.
2. After the wall is built, iterate the windows and for each one add three meshes:
   - Sill: box from yBase up to yBase+y0
   - Lintel: box from yBase+y1 up to yBase+totalH
   - Glass: thin pane (0.04m thick) at z=axisCoord, y from y0 to y1
3. Result: wall has correct full-vertical structure with hole at window y range.

The shared `addWinFlex(axis, axisCoord, w, yBase, totalH)` helper does this for both X-axis (z=const walls) and Z-axis (x=const walls).

### Big inlined HTML files: line-based tooling

The file `ozu-test.html` is now ~1000+ lines AND line 51 alone is 603 KB (the entire inlined three.js r128 library). Reading the file with `Read` works for individual sections via `offset:` and `limit:`. For grep-style scanning, use `awk 'NR!=51' file | grep ...`. For node syntax checking, `awk 'NR>=55 && NR!=51 && !/^<\//' ozu-test.html > /tmp/check.js && node --check /tmp/check.js`.

### Chrome WebGL / dev open-browser

The `package.json` `dev` script uses `concurrently` with `sleep 1 && open http://localhost:8080/index.html` to auto-open the browser after the python server starts. This is the canonical way to start the project. **Do NOT start a python server from Bash — the user's dev does it.**

### Room-1 v4 was textured; ported as flat colors

The original `room-1-3d/src/variants/v4/textures.js` loaded PBR textures (`wood_floor`, `painted_plaster_wall`, `dark_wood`) from a `/textures/` route via Vite's static-serve. ## Architecture and design notes

### Single-file architecture for the project

`ozu-test.html` is now the entire Ozu-1 project. ~1100+ lines (excluding the 603KB inlined three.js on line 51). Contains:
- HTML head + UI shell (chips, badges, hints, walk button)
- Inlined three.js r128 (line 51)
- Procedural plank texture function
- Scene registry (`scenes`, `registerScene`, `switchScene`)
- Wall helpers (`addWall`, `addWallMat`)
- 3 `registerScene` blocks: `exterior`, `interior`, `room-1`
- OrbitControls (minimal inline class)
- Walk-mode shell (currently disabled on all 3 scenes via `noFirstPerson: true`)
- Resize handler, animation loop, chip click handlers

To add a new scene (e.g. `walk` mode, time-lapse views, room-2 individual viewpoints): add a new `registerScene('id', { ... build: function(S) {...} })` block, then add a `<div class="chip" data-scene="id">label</div>` to the chip row in HTML. The existing chip handler picks it up.

### Window cut pattern (used by both 1F and 2F)

Single helper `addWinFlex(axis, axisCoord, w, yBase, totalH)` is the canonical way to add a window cut to an outer wall. The wall builder (`wallX`/`wallZ`) treats window x-ranges as gaps (just like door full-height openings); the helper adds sill (below) + lintel (above) + glass mesh in the cut.

```javascript
const F1_WIN_FRONT = [
  { a: 0.60, b: 1.20, y0: 1.50, y1: 1.80 },  // washroom
  ...
];
wallX(D, 0, W, [[4.80, 5.85], ...F1_WIN_FRONT.map(w => [w.a, w.b])], F1H, 0);
for (const w of F1_WIN_FRONT) addWinFlex('X', D, w, 0, F1H);
```

This pattern can be extended to inner walls if interior windows are needed in the future.

### Boxed-stair carriage pattern

For each step in a flight, in addition to the tread + riser meshes, add a solid box from y=0 (or floor) up to (yTop - TREAD_T) with the same x,z footprint as the tread. The result is a stair-shaped wedge that closes the underside.

```javascript
// per step:
const bodyH = yTop - TREAD_T;
if (bodyH > 0.001) {
  const body = new THREE.Mesh(new THREE.BoxGeometry(LW, bodyH, TREAD_LO), carriageMat);
  body.position.set(LXc, bodyH / 2, (z0 + z1) / 2);
  S.group.add(body);
}
```

Uses a slightly darker material (`0x7a5e3d`) than treads (`0x8a6f4d`) for subtle visual contrast.
