## Architecture and design notes

**The X-mirror wrapper pattern.** When porting a self-contained geometry block from one file (with its own local coordinate frame) into another file (with a different world frame and a blueprint X-mirror convention), wrapping the block in a `THREE.Group` with `scale.set(-1, 1, 1)` and a translation is much cleaner than rewriting every position expression. The trade-off is potential normal-map handedness flips, which are tolerable for matte/wood/painted materials but could matter for highly directional materials (anisotropic, brushed metal at oblique angles).

**Helper-shadowing inside scoped blocks.** The ported stair block defines its own `box(w, h, d, mat)` helper (matching stairs-test's 4-arg signature), which shadows the outer ozu-test `box(w, h, d, cx, cy, cz, color, extra)` helper (7-arg signature). This works because the inner `box` is inside a `{ ... }` scope. The pattern is intentional and documented; do not "fix" by renaming.

**The lightmap port limitation.** Stairs-test bakes per-surface lightmaps for its walls/ceiling/floor (`matEastWallLit`, etc.) using `setPlanarUV1()` to attach a UV1 attribute to each geometry. These lightmaps are coordinate-specific to stairs-test's frame. Did NOT port `matParapetLit` or the other `Lit` materials — used plain `matWhite` etc. for the parapet so it renders correctly regardless of UV state. If the parapet looks visually flat or under-lit compared to stairs-test, that's why; a follow-up could rebake parapet lighting for ozu-test's specific geometry.

**Parapet length is the structural compromise.** Strict verbatim port = parapet only covers the upper-flight zone, leaving the winder-zone south edge of the 2F hole unprotected. Extended parapet = small modification away from canonical. Went verbatim per the new "match X = port wholesale" rule. The user explicitly said "if it's bad I'll delete the branch" — accepting visual risk.
