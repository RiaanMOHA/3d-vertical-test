### Phase 6 — Build the QA navigation tool

Read existing chip handler code at `ozu-test.html:1480-1677` (OrbitControls + walk-mode + scene switching + populateViewChips/makeChip).

Implementation plan:
1. CSS: add `.qa-view` rules after `.tod-chip.active` (line 33 area)
2. JS module-scope helpers: `getRoomBbox(S, name)`, `clearQACull(S)`, `cullAboveY(S, cullY)`, `applyQAView(S, room, mode)` — inserted before `// ---------- Scene switching ----------` (line 1615 area)
3. Modify `populateViewChips`: create `qaRow` div, insert into `viewChipsEl`, add `showQARow` helper
4. Modify `makeChip` click handler: check `getRoomBbox(S, v.id)`, populate `qaRow` if matched, hide otherwise

Decided to scale buttons to 6 modes for MVP: `top`, `N`, `S`, `E`, `W`, `iso`, `orbit` (7 total).

View calculations per room with bbox `room`:
- `top`: `pos = [cx, room.y2 + diag*1.2, cz]`, `tgt = [cx, cy, cz]`, then `cullAboveY(S, room.y2)`
- `n`: `pos = [cx, cy, room.z1 + 0.3]`, `tgt = [cx, cy, room.z2]`
- `s`: `pos = [cx, cy, room.z2 - 0.3]`, `tgt = [cx, cy, room.z1]`
- `e`: `pos = [room.x2 - 0.3, cy, cz]`, `tgt = [room.x1, cy, cz]`
- `w`: `pos = [room.x1 + 0.3, cy, cz]`, `tgt = [room.x2, cy, cz]`
- `iso`: `pos = [room.x2 + diag*0.3, room.y2 + diag*0.6, room.z1 - diag*0.3]`, `tgt = [cx, cy, cz]`, then `cullAboveY(S, room.y2)`
- `orbit`: clear cull, restore original chip viewpoint pos/tgt

`cullAboveY` walks `S.group.traverse`, computes `bottomY = obj.position.y - (obj.geometry?.parameters?.height ?? 0) / 2`, hides if `bottomY >= cullY - 0.001`. Stores `userData._qaOrigVisible` and `_qaCulled` so `clearQACull` can restore.

`getRoomBbox` unions multiple matching `S.rooms` entries (some rooms have multiple bbox entries for irregular shapes like `corridor-2-toilet-2-f`).

Wired QA-row population in `makeChip` click handler: clear existing cull, set camera, then check if `v.id` matches any room name in `S.rooms` — if yes, call `showQARow(room, v)` (passes original viewpoint for `orbit` button restore); if no, hide qaRow.

## Problems encountered and how they were solved

### Problem 1: Room-4 cabinet rendered as transparent stripes

**Symptom.** User screenshot showed the dark wood + black metal cabinet on the right of frame as a tall narrow column with alternating dark/light bands. Looked broken.

**Root cause.** The cabinet had no back panel. Open metal frame design with 4cm-thick uprights only on E and W edges (cX0..cX0+0.04 and cX1-0.04..cX1) and 3cm-thick horizontal shelves between them. From the camera angle (SE corner looking NW), the gaps between shelves let the viewer see through the cabinet to the wall and floor behind, creating alternating dark/light stripes.

**Fix.** Added solid back panel: 2cm slab at cX0..cX0+0.02 spanning the upper shelving area (FB+0.80 to FB+1.50). Plus 2 horizontal + 2 vertical drawer-divider grooves on front face for visual 3×3 drawer hint per room map. Plus tightened to wall (cX0=3.65, was 3.70) and shifted south (cZ0=0.20, was 0.10).

**Lesson.** Open-frame furniture designs need either back panels OR visible "stuff" behind them to read correctly. A clean open frame against a plain wall reads as transparent stripes from any angle that lets the viewer see through.

### Problem 2: Navigation impossibly bad for QA

**Symptom.** User: "I cannot really see the room becasue the navigation is shit -> I want to be able to isolate any room, and see top, sides, angles, free orbit etc etc -> this is a very important QA tool we need ton build."

**Root cause.** Existing chips placed camera inside rooms, but free-orbiting from inside swings the camera through walls. Top-down would be blocked by ceiling/2F floor. Side views would be blocked by walls.

**Fix.** Built a per-room QA tool: 7 view buttons (top, N, S, E, W, iso, orbit) under each room sub-chip. `top` and `iso` auto-cull every mesh whose bottom is at or above the active room's ceiling y2. N/S/E/W place camera at opposite end of the room looking at the named wall (no cull needed since the wall behind camera is what's blocking). `orbit` clears cull and restores original chip viewpoint.

**Lesson.** "Free navigation" isn't enough — users need labeled view presets that solve the wall-occlusion problem automatically. The cull-by-bottomY approach works for any future room without per-mesh tagging.

### Problem 3: Dedicated room-1 scene 90° rotation bug

**Symptom.** Per `room-identity.md` audit, the dedicated room-1 scene had window↔closet parallel and door↔ac parallel. Per blueprint, window↔door should be parallel and closet↔ac should be parallel.

**Root cause.** Initial scene was set up with arbitrary axis assignments (window on x=RW, AC on z=RD) without checking against blueprint compass.

**Fix.** Reassigned wall features (sliding window from x=RW to z=RD, AC + frosted from z=RD to x=RW). Rotated all furniture 90° (bed long axis from x to z, desk from x=RW wall to z=RD wall, shelf to corner-cabinet-window, chair south of new desk). Updated `metalFrame` helper to auto-detect panel orientation (`if (d > w)` use z-distribution for bars, else x-distribution) so headboard/footboard render correctly when thin-in-z.

**Lesson.** Local-coord scenes still need to follow the blueprint's compass adjacency rules. The "opposite walls" check (which wall pair is opposite which) is the easiest way to detect rotation bugs — if your scene says window-wall and ac-wall are opposite, but the blueprint says window-wall and entrance-wall are opposite, you have a rotation bug.

### Problem 4: matBrick declaration scope conflict

**Symptom.** Wet rooms wanted to use `matBrick` for the laundry vanity-wall and toilet brick-wall accents. matBrick was declared at outer (function) scope at line 1075 inside the LDK section, AFTER the existing wet-room placeholders.

**Root cause.** Two `const matBrick` declarations at the same scope would fail. Wet rooms placeholders were at line 1058-1063 (BEFORE matBrick declaration at line 1075), so couldn't reference matBrick.

**Fix.** Moved the detailed wet rooms block to AFTER the LDK section (after matBrick declaration), before `// 2F rooms`. ## Learnings and discoveries

### `metalFrame` helper needed orientation detection

The original `metalFrame(panel, topRail, botRail, nBars)` function in the dedicated room-1 scene assumed panel is thin-in-x and long-in-z (a vertical headboard against an x-axis wall). Bars were distributed only along z. After 90° rotation, panels become thin-in-z and long-in-x, and the original function would bunch all bars at center cz. The fix: detect `d > w` (panel is taller in z) → distribute bars along z; else distribute along x. Useful pattern for any helper that has implicit axis assumptions.

### QA navigation cull-by-bottomY works without per-mesh tagging

I considered tagging every mesh by room (e.g. `mesh.userData.room = 'kitchen'`) so the QA tool could selectively hide non-active-room meshes. That would require modifying every furn() and wallX/wallZ call to add the tag. Instead, the simpler solution is to cull by bottomY: walk `S.group.traverse` and hide any mesh whose bottom is at or above the active room's ceiling y2. This works for any future room added to the model and doesn't require touching the build code.

### Window arrays really are single source of truth (after Phase C)

Phase C made `F1_WIN_*` and `F2_WIN_*` arrays the canonical location of all window x or z ranges. Both the exterior scene and interior scene reference these arrays. ## Architecture and design notes

### Per-room QA navigation pattern

A row of buttons appears below each room sub-chip when the chip's id matches a room name in `S.rooms`. Buttons: top, N, S, E, W, iso, orbit. Each button calls `applyQAView(S, room, mode)`:

- For `top`: position camera high above room center looking down, then cullAboveY(room.y2)
- For `n/s/e/w`: position camera at opposite end of room, looking at named wall
- For `iso`: position camera at room.x2/y2/z1 corner-iso angle, then cullAboveY(room.y2)
- For `orbit`: clear cull, restore original chip viewpoint, free orbit

`cullAboveY` walks `S.group.traverse`, computes mesh bottom = position.y - geometry.parameters.height/2, hides if bottom >= cullY. Stores `userData._qaOrigVisible` and `_qaCulled` for restore on view switch or chip switch.

`getRoomBbox(S, name)` unions multiple matching `S.rooms` entries (some rooms have multiple bbox entries for irregular L-shapes like `corridor-2-toilet-2-f`).

This pattern requires no per-mesh tagging by room. Adding a new room only requires adding it to `S.rooms` and `S.viewpoints` — the QA tool picks it up automatically.

### Per-room build pattern (Phase D scoping)

Each detailed room block is wrapped in `{...}` for material const scoping. Pattern:

```js
{
  const matIron         = new THREE.MeshStandardMaterial({ ... });
  const matBedding      = new THREE.MeshStandardMaterial({ ... });
  const matAccentPillow = new THREE.MeshStandardMaterial({ ... });
  // ... room-specific materials
  
  // Bed
  furn(...);
  // Cabinet/shelf
  furn(...);
  // Coat rack
  furn(...);
  // AC unit
  furn(...);
  // Curtains (for-loop with fold strips)
}
```

Each block can declare its own `matIron`, `matBedding`, etc. without conflicting with other rooms' blocks. Outer-scope materials (matBrick declared in LDK, matACUnit/matACGrille/matACVent declared at LDK furniture section) are referenced via closure — these MUST be declared before the room block in source order.

### Dedicated scene vs interior scene zone

The project has TWO models for each room:
1. **Interior scene zone**: a sub-region of the interior scene's group, built as part of the interior scene's `build` function. Camera is placed inside via chip `[room-name]` under interior → 1F/2F. Walls are part of the larger interior structure. Other rooms are visible (until QA top/iso cull hides them).
2. **Dedicated scene**: a stand-alone scene registered with `registerScene([room-name], {...})`. Camera orbits from outside. Walls are private to the scene (4 wall meshes only). The dedicated room-1 scene at top-level chip `room-1` is the example.

Both must follow the same compass orientation per the blueprint. The post-rotation-fix dedicated room-1 scene matches the interior scene's room-1 zone: window-wall N, ac-wall W, cabinet-wall E, entrance-wall S.
