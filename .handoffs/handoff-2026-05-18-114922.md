#### 2a. OrbitControls constructor bug fix

The prior handoff explained the bug in detail (Phase C-9 in handoff-2026-05-18-113250.md, lines 276-294). Re-verified by reading:

- `laundry-test.html` lines 210-291. Confirmed: `camera.position.set(2.40, 1.55, 2.30)` on line 213; `new OrbitControls(...)` on line 283; constructor at line 220 with `this.target = new THREE.Vector3(0.90, 0.85, 1.50)` on line 222, `this.spherical = new THREE.Spherical()` on line 223 (THIS IS THE BUG SOURCE), `this._update()` on line 228; `_update()` definition at lines 272-281 with the dual-branch logic (if `spherical.radius === 0`: `setFromVector3(offset)`; else: `offset.setFromSpherical(spherical)` then write camera.position).
- `living-dining-test.html` lines 235-313. Confirmed identical pattern (constructor at 243, spherical at 246, target at 245 = `(3.80, 1.20, 3.20)`, _update at 295-304).

**Why the bug exists:** `new THREE.Spherical()` defaults to `(radius=1, phi=0, theta=0)`. Because radius is 1 (not 0), the constructor's `_update()` call hits the **else** branch: `offset.setFromSpherical({radius:1, phi:0, theta:0})` = `(0, 1, 0)`. Then `cam.position = target + (0,1,0)` = `(0.90, 1.85, 1.50)` for laundry, `(3.80, 2.20, 3.20)` for living-dining. The original `camera.position.set(2.40, 1.55, 2.30)` is silently overwritten. The user has been looking at floor-y close-ups in standalone all this time.

**Fix considered three approaches:**
1. Change the constructor to skip the initial `_update()` call. Rejected — would leave spherical uninitialized and break the first user interaction.
2. Replace the constructor's `_update()` body inline with a 2-line "compute spherical from current offset, leave camera alone" version. Rejected — more code changes, larger diff.
3. **Chosen:** change `this.spherical = new THREE.Spherical()` to `this.spherical = new THREE.Spherical(0, 0, 0)`. With radius=0, the existing `_update()` hits the safe **if** branch and runs `spherical.setFromVector3(offset)` — recomputes spherical from the actual camera-to-target offset, leaves camera.position alone. Minimal change, no logic restructuring.

**Standalone visual impact** flagged to the user verbally: opening either file directly will now show the entry view from the position the file's `camera.position.set(...)` call intended (further back, full-room view) instead of the bugged radius=1 close-up. Journey-mode unchanged because the journey-mode block sets a NEW `camera.position` + `controls.target` AFTER the constructor and then does its own `spherical.radius = 0` reset before calling `_update()` again — that flow still works exactly as before.

Applied:
- `laundry-test.html` lines 222-227: changed `this.spherical = new THREE.Spherical()` to `this.spherical = new THREE.Spherical(0, 0, 0)` and added a 4-line explanatory comment above it.
- `living-dining-test.html` lines 245-250: identical change + identical comment.
