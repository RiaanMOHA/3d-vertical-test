```js
const ROOM1_CORNERS = [

  { id: 'corner-ac-entrance',      dotWorld: V3(0.05, 1.5, 2.65), camPos: V3(0.30, 1.55, 2.40) },

```

Each hotspot is a `<button class="corner-hotspot">` whose click calls `orbit.flyTo(c.camPos, ROOM1_TARGET)`.

**`flyTo()` method added to `OrbitControls`:** unlike `setFrom()` which copies pos+target into both current and goal (instant snap), `flyTo()` only mutates `_targetGoal` and `_sphGoal`. The existing per-frame damping (factor 0.22) lerps current toward goal over ~10–20 frames (~half a second). Smooth teleport, no jarring cut.

`updateCornerHotspots()` is called every frame from `animate()`. For each hotspot:
- If layer is hidden (not room-1), early return.
- If camera is < 0.7 m from this corner's `camPos`, hide its dot (so the dot you just clicked doesn't sit in your face).
- Otherwise project `world` to NDC via `Vector3.project(camera)`, check `v.z < 1` for in-front-of-camera, position the button via CSS `transform: translate(...)`.

Hooked into `switchScene` to toggle `cornerHotspotsLayer.hidden` based on `id === 'room-1'`.

- **Root cause:** shelf tiers (`BoxGeometry(w, ...)`) and corner posts (4 boxes at the corners of the same `f` rect) had **outer faces in the same plane**. Depth buffer can't disambiguate co-planar faces; per-pixel rasterisation alternates which one wins.
- **Fix:** shrunk tiers by `2*postT` so they fit BETWEEN the posts instead of sharing edge planes. Photo confirms this is the correct geometry anyway.
- **Pattern for next time:** any time multiple meshes share an outer plane, you'll see z-fighting. Fix with a small inset (postT, or BIAS=0.003 if cosmetic-only).

### Problem 6: User's mental model of "the GPU"

- **Symptom:** "are you using the GPU?" — user meant the *remote* GPU server, but I answered as if they meant the local one.
- **Root cause:** static-served WebGL site uses the viewer's machine GPU, but the user reasonably assumed that having a Linux GPU box meant something runs there. Reasonable misconception, common for non-developers.
- **Fix:** plain-language explanation of the rendering architecture (PDF analogy worked best — "the server can host the file, but the rendering happens in your viewer"). Showed concrete data via `nvidia-smi` of what the remote GPU IS doing (NerfStudio for a different project).
- **Saved as memory:** [`user_remote_gpu_misconception.md`](/home/moha/.claude/projects/-home-moha-Project-3d-vertical-test/memory/user_remote_gpu_misconception.md) so future sessions don't repeat the framing error.

### Problem 7: Window-glass pixelation independent of MSAA

- **Symptom:** stair-step edges on the white mullion + view-through-glass even though `WebGLRenderer({ antialias: true })` was active.
- **Root cause:** `MeshPhysicalMaterial` with `transmission > 0` renders into a separate transmission render target. r184 has a `transmissionResolutionScale` knob (default 1.0 in docs, but some build paths flip it lower).
- **Fix:** explicitly `renderer.transmissionResolutionScale = 1.0` (with feature-detect guard); raised pixel-ratio cap from 2 → 3 for retina-plus screens.
- **For next session:** any glass/refractive material complaint → check transmissionResolutionScale first, then pixel ratio.

### Problem 8: "Too complicated" controls

- **Symptom:** I shipped 6 input methods (drag, shift+drag pan, right-click pan, wheel, ctrl+wheel pinch, touch 2-finger pinch+pan, keyboard arrows, +/-). User said too much.
- **Root cause:** I conflated "more capability" with "better." For a non-developer Mac/iPad/iPhone user, two operations is the right model.
- **Fix:** stripped to drag/touch-1f orbit + wheel/pinch/touch-2f zoom. Added a top-centre hint pill that fades in on every scene entry so users don't have to remember.
- **Pattern:** for non-dev users, default to fewer controls + on-screen affordances. Rich power-user controls are a separate audience.

### Problem 9: iOS multi-breakpoint coverage was implicit, not enforced

- **Symptom:** the comprehensive controls used Mac-trackpad-only paths (`ctrl+wheel` for pinch). iOS Safari doesn't fire that — pinch comes through as 2-finger touchmove.
- **Root cause:** I built for Mac trackpad first, then bolted iOS later.
- **Fix:** rule saved as durable memory: every interactive feature must work on iPhone SE through iPad Pro at every breakpoint. Touch handlers `passive: false`, viewport `user-scalable=no`, safe-area-insets, no keyboard-only paths, sizing tested at 375 / 414 / 768 / 1024 / 1280.

### About three.js r184 specifically

- **`renderer.transmissionResolutionScale`** (Float, default 1.0) controls the resolution of the transmission render target. Pin it explicitly to be safe.

- **`+Y rotation matrix sends local +X to (cos θ, 0, −sin θ).`** So to point local +X toward world direction (cos ang, 0, sin ang), set `rotation.y = -ang`. Got this backwards in the chair spoke code initially; now there's a comment explaining it.

## Architecture and design notes

### Corner-hotspot system (new this session)

- **Pattern: world-positioned overlays projected each frame.** Each hotspot is a `<button>` in a fixed-positioned `<div>` overlay, NOT a DOM child of the canvas. The button's `transform: translate(...)` is updated each frame from the projected world position.
- **No occlusion test:** dots show even when walls would visually block the world point. This is a deliberate UX choice — the hotspots are a navigation aid, must stay discoverable from the default outside-orbit view.
- **Per-frame visibility logic:** projected `v.z < 1` (in front of camera) AND camera-to-corner distance > 0.7 m. The latter hides the dot you just clicked so it doesn't sit in your face.
- **Click handler delegates to `orbit.flyTo(camPos, target)`** — new method, smoothly damps the camera over ~10–20 frames instead of teleporting instantly.
- **Layer toggle is room-1 only** — `cornerHotspotsLayer.hidden = (id !== 'room-1')` in `switchScene`. Per-frame update early-returns if the layer is hidden, so it costs basically nothing for other scenes.

### Entry-hint pill (new this session)

- **Pattern: top-centre fixed pill, fades in/out via class toggle.** No timer-based DOM manipulation beyond `setTimeout` for the auto-hide.
- **Fired on every `switchScene` entry** including the initial bootstrap call. So users see the hint each time they enter a scene.
- **Glass-styled** to match dock + back-link via shared CSS custom properties.
- **Responsive:** `max-width: calc(100vw - 144px - safe-area)` clears the back button on small phones; `@media (max-width: 420px)` shrinks padding/font.

### `OrbitControls.flyTo` (new method)

- Distinct from `setFrom()`:
  - `setFrom(pos, target)` copies into both current AND goal → instant snap.
  - `flyTo(pos, target)` only mutates `_targetGoal` and `_sphGoal` → existing damping interpolates.
- At damping factor 0.22, ~10 frames covers ~85 % of the goal distance. ~30 frames effectively complete (≈ half a second at 60 fps).

### Bed construction split (head ≠ foot)

- **Footboard:** `pipeFrame()` — generic helper. Cylindrical bars + 2 rails + thicker end posts + collar bands + ball caps. Mirrors `corner-cabinet-window-08`.
- **Headboard:** custom inline build. Same end-post + cap detail, but with a 3-section vertical layout: bottom rail at mattress level, wood inset panel + side brackets, middle rail, upper short bars, top rail. Mirrors `corner-ac-window-{01,02}`.
- **Trade-off:** `pipeFrame` is generic and reusable; the headboard is one-off. Could be parameterised later if a third furniture piece needs the same hybrid pattern, but premature now.

### Material polish methodology

- All polish edits were targeted to specific room-1 instances. Nothing global. Important because materials with the same colour name (e.g. `matACUnit`) exist in BOTH the interior scene and the room-1 standalone scene — they must NOT be conflated.
- Roughness ranges that read correctly under the current room-1 lighting (RectAreaLight + HDRI environment + ACES tone mapping at exposure 0.55):
  - Matte plastic (AC body, switch plate, intercom plate): 0.6–0.7
  - Slightly glossy plastic (intercom button — push-button affordance): 0.35
  - Chrome (door knob, closet knobs): metalness 1.0, roughness 0.18
- These won't transfer 1:1 to the interior scene which uses different exposure and HDRI weighting.
