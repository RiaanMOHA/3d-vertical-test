## Problems encountered and how they were solved

**1. FXAA preset 12 was too subtle for jagged geometry** — initial assumption that adding FXAA would fix the "still pixelated" complaint failed. **Fix:** swapped to SMAA, which does proper edge detection + neighborhood blending. SMAAPass was already inlined in the file's three.js bundle so no download was needed. **Why:** FXAA is a post-blur approach; SMAA is sample-aware. On hard geometry edges (walls / furniture silhouettes) SMAA produces visibly cleaner results.

**2. Pillow geometry as `BoxGeometry` looked literally like cubes** — user screenshot called this out ("this is bedding? lol"). **Fix:** use `SphereGeometry(0.5, 24, 16)` with `mesh.scale.set(W, H, D)` to make a soft ellipsoid. Cubes don't read as soft cushions even when correctly sized; sphere-based geometry is the cheap shortcut to "soft pillow look" without modeling cloth.

**3. Hourglass curtain shape looked like cocktail glasses** — the cinch made the bunch read as a vase shape, not a column of fabric. **Fix:** drop the dual-tapered cone-stack, use a single nearly-cylindrical column (slight taper from `r=0.075` top to `r=0.085` bottom for natural settling weight) + tieback torus. The torus alone communicates "tied open" without needing the cinch in the column.

**4. Glass not showing through the wall** — `MeshPhysicalMaterial` with `transmission: 1.0` is the right material, but transmission in three.js shows the OPAQUE BACKGROUND through the glass — and the actual wall behind the glass pane is opaque, so all you see is the wall colour. **Fix:** cut a real hole in the wall geometry by splitting the wall into 4 segments (below / above / left / right of the cutout). With no wall geometry in the cutout area, the transmission glass renders whatever is behind, which is now the buildings backdrop.

**5. Backdrop planes blocking the sun** — once placed at `x = RW + 3.0` (between sun position and the room), the buildings backdrop plane started casting a shadow that darkened the entire room. **Fix:** in the shadow-traverse, exclude `MeshBasicMaterial` from `castShadow` AND `receiveShadow`. This is a clean tag because in room-1 the backdrops are the only `MeshBasicMaterial` meshes.

**6. Glass meshes casting hard shadows** — initial transmission glass was correctly transparent but still cast a hard rectangular shadow on the floor as if it were opaque. **Fix:** in the shadow-traverse, exclude any mesh with `material.transmission > 0` from `castShadow`. Glass mostly shouldn't drop a hard shadow; soft caustic shadows are out of scope.

**7. `Edit` tool failed once with "File has been modified since read"** — happened mid-edit, likely VS Code touching the file when the user looked at it. **Fix:** re-read the file at the relevant offset and retry the edit. Always survives a single retry.

## Learnings and discoveries

- **`THREE.SMAAPass` is already inlined** in `ozu-test.html` (line 2411 in the post-prune file). It was added during earlier work but never actually wired up — comments said "SMAA stay off, edges will be slightly jagged". Activating it is the right move for room-1; it's measurably sharper than FXAA preset 12 on hard geometry edges.
- **`MeshPhysicalMaterial` transmission requires `opacity: 1.0`, not opacity reduction.** Lowering opacity instead of using transmission gives the broken "opaque foggy panel" look from earlier in this project.
- **Transmission shows whatever is behind the glass MESH, not just the scene background.** If a solid wall sits behind a glass plane, you see the wall through the glass (because the wall is in the world). To see "outside" you must geometrically remove the wall in the cutout area.
- **`MeshBasicMaterial.isMeshBasicMaterial === true`** — useful as a discriminant in the shadow traverse to flag non-shadow-receiving backdrops.
- **`CylinderGeometry`'s 6th arg `openEnded`** removes the top/bottom caps. Crucial for lamp shades where you want to see the bulb inside.
- **The procedural env map (`buildRoom1EnvMap`) is the ambient warm-everywhere look the user later complained about.** Built from a 6-color BoxGeometry through PMREMGenerator, it bathes all PBR materials in light from every direction with no shadow correlation. It's still active. **Future:** if the user wants "where is it coming from" to read clearly, drop or attenuate this env map.
- **Three.js r128's `renderer.physicallyCorrectLights` is NOT set** in this project — transmission still works but the units aren't physically meaningful. That's fine for stylized rendering; just don't expect IES profile lookups to match reality.
- **The wall labels in code don't quite match the room-map's adjacency claims.** Code has cabinet-wall (x=0) opposite window-wall (x=W) and entrance-wall (z=0) opposite ac-wall (z=D), which is a valid floor plan. Room-map.md adjacency table says cabinet-wall and ac-wall are opposite (which is what the layout sketch suggests) — but the code's geometric reality is what you see in the renderer. **The naming inconsistency is harmless** because furniture positions in code are anchored to specific (x, z) coords, and the renderer is the source of truth for visual matching.
- **User vocabulary:** "stick to the plan" = "stop offering strategy choices, keep iterating on the photo-match work". When the user says this, batch the next several items in one turn, don't check in.
- **User collaboration style:** screenshots are concrete and the fastest feedback channel; long text proposals get ignored.
- **The previous handoff** at `.handoffs/handoff-2026-05-04-170949.md` covered the iOS Liquid Glass UI port and is now context for the dock UI that hosts the Lights toggle and the Views popover. That dock is unchanged this session but is the visible UI when entering room-1.

## Architecture and design notes

**Photo-match approach (newly established this session):**
1. Pick a wall or focused area
2. Open one panoramic photo from `ozu-test/interior-images/room-1/corner-*/` that shows it best (refer to `room-map-photos.md` for which photos show which walls)
3. List discrepancies between current code and photo (proportions / colors / details / missing objects)
4. Apply 2-5 targeted edits in one pass
5. Tell user to reload and verify, OR batch through if user says "stick to the plan"

**Procedural-texture pattern:**
- Whenever a real texture asset isn't available, wrap canvas drawing in an IIFE that returns a `THREE.CanvasTexture`
- Use a seeded LCG `s = (s * 9301 + 49297) % 233280` for deterministic randomness so re-renders are stable
- For lit textures (ceiling, walls, floor), set `roughness` 0.7-0.9
- For emissive shades, apply same texture as both `map` and `emissiveMap`
- For 2D backdrops, use `MeshBasicMaterial` so they're independent of scene lighting

**Window-with-view pattern (newly established this session):**
1. Don't try to put a transparent pane on a solid wall — you'll see the wall, not "outside"
2. Cut the wall into 4 segments around the cutout (below / above / left / right): each is a `BoxGeometry` placed individually
3. Place glass in the cutout (already handled by `feat()` helper)
4. Place a backdrop `MeshBasicMaterial` plane outside the wall, several meters away, big enough to fill the visible cone through the cutout
5. In the shadow-traverse, exclude both glass (`material.transmission > 0`) and backdrops (`material.isMeshBasicMaterial`) so glass doesn't drop hard shadows and backdrops don't block the sun

**Lamp toggle architecture:**
- `S.lampMaterial` (the shade) and `S.bulbMaterial` (the actual bulb sphere) are both stored on the scene object
- `S.lampOnIntensity = 3.0` (shade emissive when on) and `S.bulbOnIntensity = 8.0` (bulb emissive when on, brighter than shade)
- `S.lampsOn = false` is the default state
- `switchScene` applies the state to both materials AND `_room1Bloom.enabled` whenever entering room-1
- Click handler on the dock's "Lights" button mutates `S.lampsOn` and re-applies all three (shade emissive, bulb emissive, bloom enabled)

**SMAA position in pipeline:** RenderPass → UnrealBloomPass → SMAAPass. Bloom is allowed to operate on the unsmoothed render so that bright pixels bloom correctly; SMAA smooths the final image before it's shown.
