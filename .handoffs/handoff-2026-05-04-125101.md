## Problems encountered and how they were solved

### Problem 1: `cfg.fov` was a silent no-op due to missing field in `registerScene`

**Symptom**: Both `fov: 70` (added last session) and `fov: 55` (added this session) produced no visible perspective change. User reported "EXACTLY the same".

**Root cause**: `registerScene` at `ozu-test.html:176-195` builds the `S` object by listing each cfg field explicitly. Whoever added `fov` to scene configs (last session, commit 4a540b1 era? — actually added when fov was introduced, possibly even earlier) didn't update `registerScene` to copy it onto `S`. `switchScene` reads `S.fov ?? 60` and falls through to 60.

**Fix**: Added `fov: cfg.fov,` to the S object literal.

**Lesson**: When a feature spans multiple code sites (config → registry object → consumer), check the registry object actually carries the field. Pure replace-all edits won't catch this kind of plumbing miss. **Generalisable**: any time you see "I added a config option, why isn't it doing anything?", grep first for where the option is being CONSUMED, then trace BACKWARDS through the registry to where it's being COPIED. Don't assume the data flows; verify it.

### Problem 2: Tinting a brown PBR map by white can't lighten it

**Symptom**: Set `color: 0xfffaf0` on `matCeilR1` (which uses `wood_floor` PBR) — ceiling stayed visibly the same brown as the floor.

**Root cause**: In `MeshStandardMaterial`, `color` multiplies the diffuse map per-pixel. If the map is brown (~0.5, 0.3, 0.2) and color is white (1, 1, 1), result is brown. Color can only DARKEN or hue-shift; it cannot brighten beyond what's in the map.

**Fix**: Switched to a procedural canvas plank texture using the `plankTex` helper at `ozu-test.html:129`. Used a pale cream base color directly (0xebe2cd) so the texture itself is light, no multiply trick needed.

**Lesson**: For PBR materials, the diffuse map is the upper bound of brightness. To lighten an albedo, you need a different/lighter source texture, not a tint.

### Problem 3: Painted-plaster PBR has fake 3D bumps from normal map

**Symptom**: After lowering wall roughness from 0.9 to 0.4, walls still looked visibly mottled and bumpy — user: "how is this a smooth wall?"

**Root cause**: `painted_plaster_wall` PBR has THREE maps: diffuse (with noise), normal (fake 3D bumps), roughness (per-pixel variation). The scalar `roughness` value only multiplies the roughness map — it has no effect on the normal map. So the surface keeps reading as bumpy regardless of how low the scalar goes.

**Fix**: Replaced the PBR material with a plain `MeshStandardMaterial({ color: 0xa8a098, roughness: 0.55 })` for all 4 walls. No maps at all — the surface is uniform and smooth-shaded.

**Lesson**: When you want a "smooth, freshly painted" surface look, default to NO maps (plain color + scalar roughness). PBR materials with normal maps are only worth it for genuinely textured surfaces (bricks, wood, fabric) — for paint/plaster they actively hurt.

### Problem 4: Curtain occluded by shelf

**Symptom**: Right-side curtain bunch (zL, near the shelf) wasn't visible — user: "the right-side curtain does not touch the shelf".

## Learnings and discoveries

### plankTex is callable from any registerScene's build function

The `plankTex(baseHex, plankCount, seed)` helper at `ozu-test.html:129` is defined at the top level of the main IIFE — accessible from inside any `registerScene` build callback. ### Per-scene FOV now actually works

After this session's `cfg.fov` plumbing fix, scenes can configure their own FOV via `fov: <number>` in `registerScene`. `switchScene` reads `S.fov ?? 60` and updates `camera.fov` + `camera.updateProjectionMatrix()`. Currently only room-1 uses it (FOV 42). Other scenes default to 60.

### Shadows in the dedicated room-1 scene

The renderer has `shadowMap.enabled = true` globally (`ozu-test.html:81`). For shadows to be visible:
- The directional light needs `castShadow = true` and shadow camera bounds configured.
- Each mesh that should cast OR receive shadows needs `castShadow = true` / `receiveShadow = true`.
- A `S.group.traverse` loop after build is the cheapest way to flip all meshes at once.

The exterior scene's directional light at `ozu-test.html:558-569` was already configured with shadows (probably from earlier work). The interior scene was not. Room-1 was not, until this session.

The shadow camera is sized ±3 to fit the 2.7m room. Bias -0.0005 prevents shadow-acne on flat surfaces. ## CLAUDE.md updates

The session surfaced rules that may be worth adding to project CLAUDE.md (currently only the memory file has them):

1. **`registerScene` schema**: when adding a new field to scene configs, also add it to the `S` object literal in `registerScene`. The function explicitly enumerates fields rather than spreading, which is intentional (typed surface) but easy to miss when adding a new one.

2. **PBR material gotcha**: tinting a colored diffuse map by `color` can only darken/hue-shift, never brighten. To lighten, swap to a lighter texture or use a procedural canvas texture (`plankTex` helper).

3. **Smooth painted surfaces should NOT use PBR maps**: the `painted_plaster_wall` PBR has a normal map that overrides any low-roughness setting. For paint/plaster surfaces, prefer plain `MeshStandardMaterial({ color, roughness })` with no maps.

The cheapest way to set up shadows for a whole scene is `S.group.traverse(obj => { if (obj.isMesh) { obj.castShadow = obj.receiveShadow = true; } })` AFTER the build is done.

## Architecture and design notes

### registerScene now carries cfg.fov

The S object literal at `ozu-test.html:180-193` is the fixed shape of every scene's runtime state. Any per-scene config field MUST be enumerated here for it to be carried forward. Currently:

```js
const S = {
  id, group,
  walls: [],
  rooms: cfg.rooms || [],
  orbitTarget: cfg.orbitTarget,
  orbitPos: cfg.orbitPos,
  fpStart: cfg.fpStart,
  fpYaw: cfg.fpYaw || 0,
  bg: cfg.bg || 0xeef2f6,
  build: cfg.build,
  viewpoints: cfg.viewpoints || [],
  noFirstPerson: cfg.noFirstPerson,
  fov: cfg.fov,
};
```

`switchScene` reads `S.fov ?? 60`. So configs that don't set `fov` get the default 60.

### Smooth-paint pattern for walls

When a surface should read as "freshly painted, smooth, picks up shadows naturally":

```js
new THREE.MeshStandardMaterial({ color: <hex>, roughness: 0.5..0.6 })
```

NO maps. Roughness 0.55 is a sweet spot — not too matte, not too plasticky. Color picks shouldn't be too saturated (warm/cool grey neutrals work best for interior wall paint).

### Shadow setup pattern (per-scene)

```js
S.group.add(new THREE.AmbientLight(0xffffff, 0.4..0.5));  // soft fill
const sun = new THREE.DirectionalLight(0xfff4e0, 0.8..1.0);  // warm key
sun.position.set(<outside the room>);
sun.target.position.set(<inside the room>);
sun.castShadow = true;
sun.shadow.mapSize.set(2048, 2048);
sun.shadow.camera.{left,right,top,bottom} = ±<room half-size + margin>;
sun.shadow.camera.{near, far} = <camera-fits-the-light-range>;
sun.shadow.bias = -0.0005;
S.group.add(sun);
S.group.add(sun.target);
S.group.traverse(obj => { if (obj.isMesh) obj.castShadow = obj.receiveShadow = true; });
```

The traverse-after-build is necessary because individual mesh creation (`box`, `aabb`, `feat`, `winFrame`, etc.) doesn't set shadow flags.

### Procedural plank texture (plankTex) is the lightening trick

When you need a wood-look surface lighter than the available PBR diffuse maps, use `plankTex(baseHex, plankCount, seed)` at `ozu-test.html:129`. It's a top-level helper inside the IIFE, callable from any registerScene's build function. It draws a plank pattern on a 512×512 canvas with a chosen base color and configurable plank count. The returned `CanvasTexture` is already `wrapS/wrapT = RepeatWrapping`, anisotropy 8 — you set `repeat` to control density. Use as `map` in a `MeshStandardMaterial`.
