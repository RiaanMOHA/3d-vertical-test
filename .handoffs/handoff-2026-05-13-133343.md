## Learnings and discoveries

**Rattan vs linen weave in Cycles:** The key difference between the room-1 linen shader and the new rattan shader is strand thickness and weave structure. Linen uses Sin-wave bands with distortion (for irregular thread edges); rattan uses clean Sin-wave bands with no distortion (rattan strands are rigid round tubes, not soft fiber). Rattan also uses MAX of warp+weft for the brightness pattern rather than ADD, which gives a flatter top surface between crossings — matching how rigid strands read.

**rooms 2 and 4 share identical fixture:** Both use the same 4-cone spotlight cluster with the same material colors. The decision to write separate bake scripts (not one shared script) was deliberate — each room's texture directory is independent so future per-room PBR divergence is possible without refactoring.

**pbrFromBase scope pattern:** Each `registerScene` build function declares its own `function pbrFromBase(...)` at its top-level scope using `function` declaration (hoisted). The exception is the room-3 shelf block, which redeclares it as `const pbrFromBase = ...` (not hoisted, scoped to the block). This shadowing is intentional — the shelf material recipe differs slightly. Never put new top-level code inside the shelf block.

**Stair shaft wall height formula:** For any wall directly below the upper flight at x-position `Wx`, the correct height cap is: find which step's tread is directly overhead (`N` = floor((5.40 - Wx) / 0.225) + 8, where 8 is the step count at the L-bend), then cap height = `N * F1H/13 - 0.04`. The TREAD_T offset (0.04 m) ensures the wall just touches the tread underside.

**2F shaft east wall:** x=4.05 in code, x=4.725 in blueprint. The blueprint's 1F plan shows the shaft as 900 mm wide (from x=5.40 to x=4.50). But the upper flight needs 1350 mm run (6 × 225 mm). The code chose x=4.05 and all 2F geometry already uses it. The blueprint is measuring the 1F shaft footprint, not the 2F stair run. global-coords.md now explains this.

## Architecture and design notes

**PBR texture path convention:**
All baked texture sets follow: `ozu-test/room-N-textures/<fixture>/<material>/<material>_{albedo,normal,roughness,ao}.png`. The `pbrFromBase` helper in each room's scope takes the base path up to and including the material name prefix, e.g. `'ozu-test/room-2-textures/spotlight/wood/wood'` → loads `wood_albedo.png`, `wood_normal.png`, etc.

**Per-room pbrFromBase isolation:**
Each `registerScene` build function declares its own `function pbrFromBase` to avoid closure issues across room build calls. The room-3 shelf block additionally shadows it with a `const pbrFromBase` inside its own `{}` block — this is intentional but means new top-level room-3 PBR calls should NOT be placed inside the shelf block.

**Bake-script parallelism:**
Rooms 2 and 4 share the same fixture design but have separate bake scripts and separate texture directories. This is deliberate: the CLAUDE.md rule says "every object pass must engage the A6000", and keeping per-room texture dirs makes future per-room divergence trivial. To re-bake if material recipes change: `CUDA_VISIBLE_DEVICES=1 ~/blender/blender-5.1.1-linux-x64/blender --background --python ozu-test/bake/bake_room<N>_<fixture>.py`.

**Stair wall height caps — formula:**
For a wall at x-position Wx directly below the upper flight:
- The step directly overhead is N where the tread occupies x=[5.40 - N×0.225, 5.40 - (N-1)×0.225]
- Cap height = `N * F1H/13 - TREAD_T` where F1H=2.50, TREAD_T=0.04
- Step 12: cap = 2.27 m; Step 13 (last step): cap = 2.46 m; Full height east of landing: F1H = 2.50 m
