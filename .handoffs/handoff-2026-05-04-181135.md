## Architecture and design notes

**The v4 audit prompt's structure** (worth keeping as a template for future Phase 0 prompts):

- **Verdict definitions up top** (Green / Yellow / Red with explicit definitions).
- **Parallel-variant rule** (constraint that downstream phases must respect; restated 3x in different sections).
- **Machine + structure confirmation gate** (`pwd && hostname && whoami` + 3 path existence checks; HARD STOP if any fail).
- **Two-machine context** (where the audit runs vs. where future training jobs run; separates concerns).
- **Key principle (read twice)** (audit-only, no build, no install).
- **User-request → task mapping table** (every user-facing requirement maps to one or more audit tasks producing a verdict).
- **Stack table** (every layer with a candidate library and source URL).
- **Inputs table** (every required path; STOP if missing).
- **Tasks** (numbered, each writing to its own notes file under `room-1-3d/notes/v5-*.md`, with clear "do this / do NOT do that" structure).
- **Consolidated report task** (re-reads all notes files via `cat` to synthesize from content, not memory; produces verdict tables, observed structure, open questions, phase roadmap).
- **Constraints** (read-only on existing files, write allowlist, "needs prototype" escape hatch, scope guard).
- **Acknowledge before starting** (5-step ack including machine + structure + path checks).

**Cross-layer dependency tracking** is the most rigorous part of the v4 prompt. The WebXR + WebGPU compatibility check is treated as a chain-effect: if AR forces a WebGL fallback, three stack-layer verdicts downgrade. The prompt explicitly threads this dependency from Task 10 → Section 6 of the consolidated report so the synthesis step cannot lose it. Future audit prompts in this codebase should follow the same pattern: each task that surfaces a cross-layer dependency must explicitly tell the consolidation step where to thread the dependency.

**Why save both v1 and v4:** the user's iteration of the prompt is itself a record of how rigor was added. v1 had no machine check, no WebGPU/WebXR chain-effect, no parallel-variant rule, no "synthesize from notes" gate, no cloud cost bounding, no exposure-consistency check, no splat-window-masking sub-question. v4 has all of these. Keeping v1 as a reference lets future sessions see what gaps the iteration closed and apply the same lessons to new audits.
