## Architecture and design notes

### `pbrFromBase` is the canonical PBR helper for Cycles-baked materials

Every room sandbox now has a function-scoped `pbrFromBase(base, repU, repV, extras = {})` declared right after `pbrMatR<N>`. It loads 4 PNGs (`<base>_albedo.png`, `_normal.png`, `_roughness.png`, `_ao.png`), sets `RepeatWrapping`, applies max anisotropy, and returns a `MeshStandardMaterial` with all 4 maps assigned.

Argument: `base` is a FULL path including file prefix (e.g. `'ozu-test/room-1-textures/bed/white_iron/white_iron'`). NOT just a slug.

The older `pbrMatR<N>` helper (jpg-based, _diff/_nor_gl/_rough suffix) is for the external Poly Haven texture sets (wood_floor, dark_wood). For NEW Cycles bakes from `bake_room*_*.py` scripts, always use `pbrFromBase` instead.

2 levels: `<object>/<material>/`. Material slug appears as both directory name AND filename prefix. The pendant pattern from the prior session is the model — when adding new bakes, follow this layout.

### When to share a PBR bake vs. duplicate

Established rules from this session and the prior one:

- **Share** when the photo evidence shows the SAME material in multiple rooms (cream cotton sheet, ABS AC plastic, dark stained pine, matte black iron).
- **Share** when the only difference is color tint — adjust via `extras.color` or a different material wholesale.
- **Don't share** when the rooms have visually distinct materials (room-2's painted white iron bed vs. room-1's dark iron bed). Even if both are "iron beds", paint vs. raw iron is a different bake.

### Lights toggle reuses S.lampMaterial / S.bulbMaterial / S.lampPointLights pattern

Every room sandbox exposes:
- `S.lampMaterial` — the shade material (emissive when on)
- `S.bulbMaterial` — the bulb material (emissive when on)

### Bloom composer architecture (if reactivated)

If user decides to reactivate bloom after QA, the architecture would be:
- One `EffectComposer` per bloom-enabled scene (room-1, plus rooms 2/3/4 if extended)
- Pass chain: `RenderPass(scene, camera) → UnrealBloomPass(resolution, strength, radius, threshold) → SMAAPass(width, height)`
- Replace `renderer.render(scene, camera)` with `composers[id].render()` in the render loop for those scene IDs
- Window resize: call `composer.setSize(w, h)` for each composer
- Lights toggle: `composer.passes[1].enabled = lampsOn` (the UnrealBloomPass at index 1)

### CLAUDE.md `box()` gotcha note checklist (for future PBR conversions)

Adding to the documented pattern:
1. Identify the surface group that needs PBR (e.g. AC body, hutch panels, cabinet drawers).
2. Run the Cycles bake → produce 4 PNGs.
3. Declare `const matFoo = pbrFromBase('path/to/material', repU, repV, extras)` at the top of the surface scope.
4. **AUDIT THE SURFACE GROUP FOR `box()` AND `aabb()` CALLS.** Grep `box.*0x` and `aabb.*COL` inside the scope.
5. For every `box()/aabb()` call that needs the new PBR: replace with `<x>Box()` helper that uses `matFoo`, OR replace with direct `new THREE.Mesh()` call.
6. Test render — if any surface still shows the old flat color, audit was incomplete.
